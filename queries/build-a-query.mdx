**Queries** let you answer precise questions about your data—"households in Oregon who gave over \$100 last year," "individuals with no email on file," and so on. Open **Queries** in the sidebar.

## Pick what you're looking for

Start by choosing the **result mode**—what each row in your results represents:

| Result mode | One row represents |
| --- | --- |
| Contacts | A household, organization, or foundation |
| Individuals | A person, including their contact methods |
| Gifts | A recorded contribution |

Choose Individuals for email-list actions and Contacts for household-level tags or notes.

<Note>
  Switching modes clears your current conditions and results, since each mode has its own set of fields.
</Note>

## Build the conditions

<Steps>
  <Step title="Add a condition">
    Each condition is a **field**, an **operator**, and a **value**—for example, _State_ / _is one of_ / _CA, OR, WA_.
  </Step>
  <Step title="Combine with AND / OR">
    Set the group logic: **AND** requires every condition; **OR** matches any. You can nest groups for more complex logic.
  </Step>
  <Step title="Execute">
    Choose **Execute**, then pick which **fields** (columns) to show in your results.
  </Step>
  <Step title="Save (optional)">
    Choose **Save**, name the query, and optionally **share it with your team**.
  </Step>
</Steps>

## The kinds of filters

Fields span contact info, the people in a household, contact methods (email/phone and opt-in status), addresses (down to congressional district), tags, giving, memberships, and events. Operators adapt to the field—text supports _contains_ and _starts with_; numbers and currency support _greater than_ and _between_; dates support _in the last N days_; tags support _has tag_ and _doesn't have tag_.

### Event and membership gifts

Gifts recorded by the Events module (tickets, merchandise, auction wins, sponsorships) and gifts that paid for a membership carry extra fields you can filter on in any result mode:

- **Is Event Gift** / **Event (Gift)** / **Event Gift Type** — under the **Events** category. Types are _Ticket_, _Merchandise_, _Auction win_, and _Sponsorship_; imported event gifts with no type are _Unspecified (imported)_.
- **Is Membership Gift** / **Membership Gift Tier** — under the **Memberships** category.

In **Gifts** mode these filter the transactions themselves (for example, every ticket gift for the Fall Gala). In **Contacts** or **Individuals** mode they find the people who have such a gift.

### Event registration and attendance

These fields are in the **Events** category, in **Contacts** and **Individuals** modes:

- **Registered for an Event (purchaser)** and **Registered for Event (purchaser)** find people who bought a registration. They include buyers whose registration was never matched to a contact, by using the email given at checkout.
- **Attending an Event (incl. guests)** and **Attending Event (incl. guests)** also find people named as guests on someone else's registration.

<Note>
  A guest counts only after being matched to a person. Clear the **Guests** tab in [Event match](/data-management/event-match) before relying on attendance results.
</Note>

## Saved queries

The **Saved queries** tab lists everything you've saved. Filter by search, result mode, and ownership; click any query to load it back into the builder to run, adjust, or remove.

<Tip>
  A query is the fastest way to build a one-time list. If you want an audience that keeps itself current for email, build a [segment](/email/lists-and-segments) instead.
</Tip>

## Check your results

Start with a narrow example whose outcome you can verify. Inspect several rows after executing, then adjust the conditions. AND requires every condition in the group; OR permits any condition. Use nested groups when those rules need to be combined. Re-execute after editing conditions before using a bulk action.

For no results, remove conditions one at a time and confirm the result mode. For too many results, check OR groups and whether an empty condition is broadening the query. See [Act on selected results](/queries/bulk-actions) before editing records in bulk.
